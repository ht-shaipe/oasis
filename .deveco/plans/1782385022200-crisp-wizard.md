## Goal

Provide a complete, self-contained embedding model management experience where users can:
1. Choose between **Local** (fastembed/ONNX) and **Remote** (API-based) embedding
2. Browse HuggingFace embedding models, select one, and download with **real progress**
3. Auto-activate (or manually activate) a model after download
4. See clear model states: Not Downloaded → Downloading (with %) → Downloaded → Active
5. Delete downloaded models, switch active model at any time

## Scope / Non-goals

**In scope:**
- Custom `hf-hub` download with Tauri event-based progress (per-file + overall)
- HuggingFace model browser (search + curated list, NOT full API search — too complex/unreliable)
- Auto-activate option after download
- Full model lifecycle in EmbeddingModelPanel: browse → download → activate → delete
- Remote mode: reuse existing LLM embedding models from LlmPanel (already works)
- KnowledgePanel syncs with active model state

**Out of scope:**
- Full HuggingFace API search (rate-limited, requires API token, complex filtering) — use a curated, extensible catalog instead
- ONNX model conversion (only support models that already have ONNX files on HF)
- Model performance benchmarking UI

## Current State And Constraints

### What's broken
- `download_embedding_model` is a black box — no progress, just a spinner until done/fail
- Model catalog is hardcoded to 6 models — users can't add custom HF models
- No model "state" visibility — users don't know if a model is downloading, downloaded, active, or errored
- `embed_config.json` only stores `active_model_id` — no per-model tracking, no remote config
- Remote embedding mode requires going to LlmPanel separately — no unified config

### Technical constraints
- **fastembed v5.17.2** uses `hf_hub::api::sync::Api` internally via `TextEmbedding::try_new()`
- **hf-hub v0.5.0** has `Progress` trait and `download_with_progress()` — we can use this directly
- **Strategy**: Use `hf_hub::api::sync::Api` with custom `Progress` impl that emits Tauri events, then call `TextEmbedding::try_new()` which finds cached files and skips download
- **Tauri event pattern**: Already established — `app.emit("event-name", payload)` in Rust, `listen('event-name', cb)` in Vue
- **Cache dir structure**: `embed_models/models--<org>--<model>/snapshots/<commit>/<files>` — hf-hub manages this
- **Model files needed**: tokenizer.json, config.json, special_tokens_map.json, tokenizer_config.json + ONNX model file(s)
- **Tauri command registration**: Code-generated via `build.rs` — just need `#[tauri::command]` annotation

### Existing event pattern reference
- Rust emit: `commands.rs:472` → `app.emit("update-download-progress", progress_u32)`
- Frontend listen: `useAppUpdate.ts:87` → `listen<number>('update-download-progress', cb)`

```rust
#[derive(Serialize, Deserialize, Clone, Debug, Default)]
#[serde(rename_all = "camelCase")]
pub struct EmbedModelConfig {
    pub mode: EmbedMode,                    // "local" | "remote"
    pub active_local_model_id: Option<String>,
    pub active_remote_model_id: Option<String>,

    Remote,

#[derive(Serialize, Deserialize, Clone, Debug)]
#[serde(rename_all = "camelCase")]
pub struct CustomModelEntry {

    pub onnx_file: String,          // "onnx/model.onnx" or "onnx/model_quantized.onnx" etc.
```

### 2. Rust: Custom download with Tauri event progress

**File: `crates/embed/src/commands.rs`**

Add `hf-hub` as direct dependency (it's already transitive via fastembed, but we need it directly for the `Progress` trait).

New `download_embedding_model` implementation:

```rust
use hf_hub::api::sync::ApiBuilder;
use hf_hub::api::Progress;
use tauri::Emitter;

struct TauriProgress {
    app: tauri::AppHandle,
    model_id: String,
    file_name: String,
    total: usize,
    current: usize,
}

impl Progress for TauriProgress {
    fn init(&mut self, size: usize, filename: &str) {
        self.total = size;
        self.file_name = filename.to_string();
        self.current = 0;
        let _ = self.app.emit("embed-download-progress", serde_json::json!({
            "modelId": self.model_id,
            "fileName": filename,
            "total": size,
            "current": 0,
            "percentage": 0,
            "status": "downloading"
        }));
    }
    fn update(&mut self, size: usize) {
        self.current = size;
        let pct = if self.total > 0 { (size * 100 / self.total) as u32 } else { 0 };
        let _ = self.app.emit("embed-download-progress", serde_json::json!({
            "modelId": self.model_id,
            "fileName": self.file_name,
            "total": self.total,
            "current": size,
            "percentage": pct,
            "status": "downloading"
        }));
    }
    fn finish(&mut self) {
        let _ = self.app.emit("embed-download-progress", serde_json::json!({
            "modelId": self.model_id,
            "fileName": self.file_name,
            "total": self.total,
            "current": self.total,
            "percentage": 100,
            "status": "file_done"
        }));
    }
}
```

The download command downloads each required file (tokenizer files + ONNX file(s)) with progress, then does a lightweight verification:

```rust
#[tauri::command]
pub async fn download_embedding_model(
    app: tauri::AppHandle,
    model_id: String,
    auto_activate: Option<bool>,
) -> Result<bool, String> {
    // 1. Find model entry (catalog or custom)
    // 2. Build hf_hub sync Api with same cache_dir
    // 3. For each required file, call repo.download_with_progress(file, TauriProgress{...})
    // 4. Emit "embed-download-complete" with model_id
    // 5. If auto_activate == true, set as active model
    // 6. Return true if auto-activated
}
```

## Risks And Compatibility

| Risk | Mitigation |
|---|---|
| hf-hub v0.5 `download_with_progress` signature may differ from docs | Pin exact version already in lockfile; test with a small model first |
| `Progress::init()` total size may be 0 for some HF files (Content-Length missing) | Handle `total == 0` gracefully — show "Downloading..." without percentage |
| Download cancellation | Use `AtomicBool` flag checked in `Progress::update()` — if cancelled, the read() wrapper returns Error |
| Config migration | If old `embed_config.json` has `activeModelId` but no `mode`, default to `Local` mode with `activeModelId` → `activeLocalModelId` |
| Large model download blocks Tauri main thread | `download_embedding_model` is `async` — runs on `spawn_blocking`, so UI stays responsive |
| China users can't reach huggingface.co | HF_ENDPOINT env var support — already handled by hf-hub's `with_endpoint()` |
