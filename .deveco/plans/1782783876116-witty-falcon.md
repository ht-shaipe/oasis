# Jishu Hub → Oasis 核心功能迁移计划

## Goal

将 Jishu Hub（React + Tauri 2, Windows）的 **CLI 智能体管理核心能力** 迁移到 Oasis（Vue 3 + Tauri 2, macOS），使 Oasis 支持：
1. 多 Agent（Claude Code + Codex）切换对话
2. 按项目分组的会话发现与管理
3. 工具调用可视化（ShellExec / FileEdit / Search body 类型）
4. 配置预设与自动备份

## Scope / Non-goals

**包含**：
- 新建 `oasis-project` crate，整合 JSONL 会话解析 + macOS 项目发现
- 添加 Codex adapter 到 `oasis-agent` crate
- 增强 `AgentPlugin` trait 支持 `scan_projects` 跨 agent 合并
- 增强 `AgentChatView` UI：类型化 ToolCallCard body、SessionList 增强
- 新增 `ProjectManager` 应用窗口
- 配置预设/备份功能（`oasis-ai` 增强 + 前端 UI）

**不包含**：
- OpenCode ACP 协议迁移（迁移文档明确排除，需额外 3-5 天）
- ACP runtime（opencode 专用，暂不需要）
- Jishu Hub 的环境检测/版本更新功能（Windows 特有逻辑）
- `install_agent_command`（Windows PowerShell 安装命令执行）

## Design

### 阶段 0：脚手架 + `oasis-project` crate 创建

**创建 `oasis-project` crate**：将 JSONL 会话解析和项目发现从 `oasis-agent/adapters/claude_code.rs` 中提取出来，形成独立可复用的 crate。这样 Codex adapter 也能调用项目/会话功能，而不需要在每个 adapter 中重复实现。

文件结构：
```
src-tauri/crates/project/
├── Cargo.toml
└── src/
    ├── lib.rs           # crate 入口
    ├── project.rs       # 项目发现（macOS 版）+ 跨 agent 合并
    ├── session.rs       # JSONL 解析（从 Jishu Hub session.rs 移植）
    └── commands.rs      # Tauri commands（可选，项目/会话相关）
```

依赖关系：
- `oasis-project` 依赖 `serde`, `serde_json`, `chrono`, `dirs-next`
- `oasis-agent` 依赖 `oasis-project`
- 主 crate `oasis` 依赖 `oasis-project`（如果 `oasis-project` 自己注册 command）

**注意**：考虑到现有 `oasis-agent` 的 `plugin.rs` 中 `AgentPlugin` trait 已经包含了 `scan_projects`, `list_sessions`, `load_session_messages` 等方法，且每个 adapter 自己实现了这些方法，**更务实的方案**是：
- 将公共的 JSONL 解析逻辑抽取到 `oasis-project` crate
- `oasis-agent` 的各 adapter 调用 `oasis-project` 的解析函数
- 项目发现逻辑留在各 adapter 中（因为不同 agent 的项目目录不同：Claude → `~/.claude/projects/`，Codex → `~/.codex/sessions/`）

### 阶段 1：Codex Adapter + 单 Agent 对话增强

**1.1 添加 Codex adapter**

从 Jishu Hub `adapters/codex.rs`（692 行）移植核心逻辑到 `oasis-agent/adapters/codex.rs`：
- `CodexAdapter` struct + `AgentPlugin` 实现
- `normalize_stream_event`（Codex 的 JSON 流格式解析）
- `build_chat_command`（macOS 版：直接 `codex exec --json <message>`，去掉 Windows `cmd /C` 逻辑）
- `scan_projects`（Codex 项目发现：读 `~/.codex/.codex-global-state.json`）
- `list_sessions` / `load_session_messages`（Codex 用 rollout JSONL，不同于 Claude）
- `probe_sync`（用 `which codex` + 候选路径）
- `open_in_terminal`（用 macOS `osascript` 启动 Terminal.app）

**1.2 注册 Codex 到 AgentRegistry**

修改 `oasis-agent/src/plugin.rs` 的 `AgentRegistry::new()`，添加 Codex adapter：
```rust
let codex = crate::adapters::codex::CodexAdapter::new();
let codex_id = codex.info().id.clone();
agents.insert(codex_id, Box::new(codex));
```

**1.3 增强 runtime 的 normalize_event 分发**

修改 `oasis-agent/src/runtime.rs` 的 `normalize_event` 函数，添加 Codex 分支：
```rust
fn normalize_event(agent_id: &str, event: &serde_json::Value) -> Vec<NormalizedEvent> {
    match agent_id {
        "claude-code" => crate::adapters::claude_code::normalize_stream_event(event),
        "codex" => crate::adapters::codex::normalize_stream_event(event),
        _ => vec![NormalizedEvent::Raw { ... }],
    }
}
```

**1.4 添加 `oasis-agent` Cargo.toml 的 `dirs-next` 依赖**（已有）

### 阶段 2：会话与项目管理增强

**2.1 增强 JSONL 会话解析**

从 Jishu Hub `session.rs` 移植以下功能到 `oasis-project/src/session.rs`：
- `smart_summary()`：首句摘要（中英文通用）
- `parse_ai_title()`：从 JSONL 的 `ai-title` 类型行提取标题
- `merge_tool_results()`：将 user 消息中的 tool_result 合并到前一条 assistant
- `ContentBlock` 的完整解析（ToolUse、ToolResult、Thinking）

然后让 `oasis-agent/adapters/claude_code.rs` 的 `load_claude_session_messages` 调用 `oasis-project::session` 的解析函数。

**2.2 增强项目发现 — 跨 agent 合并**

在 `oasis-agent/src/plugin.rs` 的 `AgentRegistry` 中添加：
```rust
pub fn scan_all_projects(&self) -> Vec<ProjectEntry> {
    let mut projects = Vec::new();
    for agent in self.agents.values() {
        projects.extend(agent.scan_projects());
    }
    merge_projects(projects)
}
```

`merge_projects` 逻辑：同 `encoded_name` 的项目合并 `session_count`、`agent_id` 列表。

**2.3 修改 `agent_scan_projects` 命令**

改为调用 `scan_all_projects()` 而非 `reg.active().scan_projects()`，这样前端可以看到所有 agent 的项目。

**2.4 SessionList 增强 — 显示 display_name**

在 `oasis-agent/adapters/claude_code.rs` 的 `list_claude_sessions` 中：
- 解析 JSONL 的 `ai-title` 行生成 `display_name`
- 回退到首条 user 消息的 `smart_summary`

**2.5 "继续对话"功能**

现有的 `build_chat_command` 已支持 `--resume` 参数，前端只需在 `sendMessage` 时传入 `sessionId`。

**3.3 ToolCallCard 类型化 body**

增强 `AgentToolCard.vue`，根据 tool name 分派不同的 body 组件：

```
ToolCallCard.vue (修改)
├── ShellExecBody.vue   # 新建 - bash/cmd/shell 命令执行可视化
├── FileEditBody.vue    # 新建 - edit/write 文件编辑（diff 或 code）
├── SearchBody.vue      # 新建 - search/grep 搜索操作
└── OtherBody.vue       # 新建 - 通用 fallback
```

每个 body 组件判断逻辑：
- `tool.name` 包含 `bash`/`cmd`/`shell` → ShellExecBody
- `tool.name` 是 `edit`/`write`/`multiEdit` → FileEditBody
- `tool.name` 是 `search`/`grep`/`glob` → SearchBody
- 其他 → OtherBody

**ShellExecBody.vue**：显示命令（从 input 提取）+ 输出（从 output 提取），可折叠。

**FileEditBody.vue**：显示文件路径 + 编辑内容，利用 Oasis 已有的 Monaco Editor（`CodeEditor.vue`）做 diff 视图（如果可行），或简单的 pre-formatted text。

**3.4 ThinkingBlock 增强**

- 折叠时显示 "思考过程 (N字)"

## Risks And Compatibility

| 风险 | 说明 | 缓解 |
|------|------|------|
| Codex 未安装 | macOS 上 Codex 需要 `npm i -g @openai/codex` | AgentHealthPanel 显示安装引导 |
| Codex session 格式差异 | Codex 用 rollout JSONL + 全局索引，不同于 Claude 的 per-project JSONL | 移植 Jishu Hub 已验证的逻辑 |
| Rust edition 2024 | 某些 2021 语法可能不兼容 | 逐步编译验证 |
| `dirs-next` vs `dirs` | Oasis 用 `dirs-next`，Jishu Hub 用 `dirs` | 统一用 `dirs-next` |
| AgentChat 现有改动干扰 | 增强 UI 可能引入 bug | Agent 模式独立 composable，与 LLM Chat 分离 |
| ToolCallCard 重构 | 替换现有通用版本可能破坏 | 保持向后兼容，OtherBody 作为 fallback |
| `oasis-project` crate 依赖链 | 新增 crate 增加编译复杂度 | 保持 crate 精简，仅含解析逻辑 |

## Rollback

1. 所有 Rust 代码变更可通过 `git checkout` 回退
2. `oasis-project` crate 可通过移除 Cargo.toml 依赖 + 删除目录回退
3. Codex adapter 可通过移除 `adapters/codex.rs` + 从 `AgentRegistry::new()` 移除注册回退
4. 前端组件新增文件直接删除，修改文件通过 git revert
5. Settings 预设 UI 可独立移除，不影响核心功能
