# Local LLM Chat Model Support

## Goal

Allow users to download and run small LLM chat models (135M-1.7B params) directly within the app, no external Ollama required. Mirrors the embedding model UX: catalog → download → activate → use.

## Scope / Non-goals

**Included:**
- New `oasis-local-llm` crate with `mistralrs` (pure Rust, Metal support)
- 3 curated small models: SmolLM2-135M (~90MB), SmolLM2-360M (~220MB), SmolLM2-1.7B (~1GB)
- Download from HuggingFace with progress events (reuse `hf-hub`)
- Streaming token generation via existing `Channel<StreamChunk>` IPC
- Settings panel for download/delete/activate
- Local models appear as "Local" provider in ChatView
- Apple Metal acceleration

**Not included:**
- Models >1.7B (future work — same architecture, just more catalog entries)
- Custom GGUF import, LoRA, multimodal, CUDA
- ONNX text generation

## Current State And Constraints

- Embedding models: fully working via `fastembed` + `ort`
- Remote LLM chat: working via `ai-llm-kit` HTTP client
- Ollama: as a remote HTTP provider only
- `LlmService` trait uses `#[async_trait(?Send)]` → `spawn_blocking` required
- Tauri commands auto-registered via `build.rs` scanning `#[tauri::command]`
- No local in-process LLM chat exists

## Design

### Architecture

```
ChatView ──▶ ai_chat_stream ──┬── provider=="local" ──▶ oasis-local-llm (mistral.rs)
                              └── provider!="local" ──▶ ai-llm-kit (HTTP)
```

When `provider == "local"` in the model config, `ai_chat_stream` dispatches to `oasis-local-llm` instead of the HTTP client.

**Module structure**:

### 2. Model Catalog (3 models)

| ID | Name | Params | Q4 Size | License |
|---|---|---|---|---|
| `HuggingFaceTB/SmolLM2-135M-Instruct` | SmolLM2 135M | 135M | ~90MB | Apache 2.0 |
| `HuggingFaceTB/SmolLM2-360M-Instruct` | SmolLM2 360M | 360M | ~220MB | Apache 2.0 |
| `HuggingFaceTB/SmolLM2-1.7B-Instruct` | SmolLM2 1.7B | 1.7B | ~1GB | Apache 2.0 |

Each entry: `id`, `name`, `params_billions`, `size_mb`, `license`, `description`, `hf_repo`, `gguf_file_pattern`.

Note: GGUF files on HuggingFace are typically at paths like `<repo>/SmolLM2-135M-Instruct-Q4_K_M.gguf`. The catalog maps model ID → exact repo + filename.

### 3. Config (`config.rs`)

```rust
#[derive(Serialize, Deserialize, Clone, Debug, Default)]
#[serde(rename_all = "camelCase")]
pub struct LocalLlmConfig {
    pub active_model_id: Option<String>,
    pub hidden_ids: Vec<String>,
}
```

Stored as `local_llm_config.json` in app data dir.

### 4. Download Flow (mirrors embed crate)

1. `download_local_chat_model(model_id)` command
2. Resolve to `hf_repo` + `gguf_file` from catalog
3. `hf_hub::ApiBuilder` with `local_llm_models/` cache dir
4. Download GGUF file, emit `local-llm-download-progress` Tauri events
5. Cancel via global `AtomicBool`
6. On success, auto-activate if config says so

### 5. Inference (`inference.rs`)

**Model caching** — unlike embeddings (loaded per-call), chat model stays in memory:
```rust
static GLOBAL_MODEL: Lazy<Mutex<Option<Arc<MistralRs>>>> = Lazy::new(|| Mutex::new(None));
static ACTIVE_MODEL_ID: Lazy<Mutex<Option<String>>> = Lazy::new(|| Mutex::new(None));
```

- `load_model(model_id, cache_dir)` → load GGUF, store in `GLOBAL_MODEL`
- `unload_model()` → drop from memory
- `is_model_loaded()` → check GLOBAL_MODEL
- If user switches model, unload old → load new (with loading state event)

**Streaming chat**:
```rust
pub fn chat_stream(
    messages: Vec<ChatMessage>,
    on_chunk: impl Fn(StreamChunk) + Send + 'static,
) -> Result<(), String> {
    let model = GLOBAL_MODEL.lock().unwrap().clone().ok_or("No model loaded")?;
    // Use mistral.rs sender/receiver pattern for streaming
    // For each token: on_chunk(StreamChunk { content: token, is_over: false })
    // On complete: on_chunk(StreamChunk { is_over: true, usage: ... })
}
```

**Loading state**: emit `local-llm-loading-progress` events during model initialization (5-30s).

### 6. Tauri Commands

| Command | Purpose |
|---|---|
| `list_local_chat_models` | Catalog + download status + active flag |
| `download_local_chat_model` | Download GGUF from HF |
| `cancel_local_chat_download` | Cancel active download |
| `delete_local_chat_model` | Remove downloaded GGUF |
| `set_active_local_chat_model` | Activate model (load into memory) |
| `unload_local_chat_model` | Unload from memory |
| `get_local_chat_config` | Return config |
| `get_local_chat_model_status` | Loaded? Loading? Memory? |

The actual streaming chat is called internally by `ai_chat_stream` (not a separate Tauri command) to reuse the existing `Channel<StreamChunk>` frontend integration.

### 7. Dispatch Integration (`oasis-ai/src/commands.rs`)

In `ai_chat_stream`, after looking up the model config:
```rust
if model.provider == "local" {
    // Ensure model is loaded
    oasis_local_llm::inference::ensure_loaded(&model.model_id, &app_data_dir)?;
    // Run streaming inference inside spawn_blocking
    let model_id = model.model_id.clone();
    tauri::async_runtime::spawn_blocking(move || {
        oasis_local_llm::inference::chat_stream(messages, on_chunk)
    })
} else {
    // Existing remote flow
}
```

**Auto-register in `llm_config.json`**: When a local model is activated, auto-create a `LlmModel` entry with `provider: "local"`, `model_type: "chat"`, `enabled: true`. This makes it visible in ChatView without frontend changes.

- Active model card (if any) with "使用中" badge
- Available models list with download/activate buttons
- Download progress per model

Add to Settings sidebar: "本地模型" between "向量化模型" and "LLM".

## Risks And Compatibility

| Risk | Mitigation |
|---|---|
| `mistralrs` API changes (pre-1.0) | Pin exact version; wrap behind internal trait |
| `mistralrs` + Metal feature compilation issues | Test early; fallback to CPU-only feature |
| Model loading blocks main thread | All in `spawn_blocking`; UI shows loading state |
| SmolLM2 quality limitations | 1.7B is decent; 360M/135M for fast/simple tasks only |
| GGUF filename varies on HF | Catalog maps exact filenames per model |
